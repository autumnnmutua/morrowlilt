# 阶段 1 验收清单

供测试工程师依据 `docs/PRD.md` 直接设计和执行用例。阶段 1 只交付需求文档；以下业务项应在对应实现阶段标记结果。

## 0. 测试准备

- [ ] 可固定服务端业务时钟和 IANA 时区。
- [ ] 可注入内容 Provider、词典 Provider、Resend 的成功、超时、限流和异常响应。
- [ ] 可创建题库充足与题库不足两套数据。
- [ ] 可查看数据库状态但不依赖生产数据或真实邮箱。
- [ ] 可分别模拟两个客户端及重复幂等请求。

## 1. 每日内容

- [ ] **D-01 每日不同**：固定相邻两个业务日分别生成内容；确认 `content_date`、`content_version` 不同，核心学习项不完全相同。（AC-D01）
- [ ] **D-02 当日稳定**：生成今天快照后改变 Provider 响应并刷新；确认仍返回原快照。（AC-D02）
- [ ] **D-03 联网来源**：Provider 成功时检查快照包含来源、拉取时间、版本和许可元数据，客户端看不到 secret。（FR-D02）
- [ ] **D-04 降级链路**：依次验证“已有当日快照 → 最近有效缓存 → 内置应急内容”，并确认降级原因可观测。（FR-D04）
- [ ] **D-05 完全失败**：令三个来源均不可用；确认页面显示可重试错误，空内容不能被标记已学习。（AC-D03）

## 2. 打卡与结清

- [ ] **C-01 默认未学习**：进入新业务日，仅打开、滚动和关闭页面；确认 `settled_through_date` 不变。（AC-C01）
- [ ] **C-02 显式未学习**：点击“今天先不学”；确认边界不变且没有完成事件。（FR-C03）
- [ ] **C-03 积压叠加**：把边界设为三天前；确认页面按日期升序显示之后至今天的全部内容。（AC-C02）
- [ ] **C-04 次日继续叠加**：保持未结清并推进一个业务日；确认旧包完整保留并增加新日内容。（AC-C02）
- [ ] **C-05 整包完成**：确认按钮说明会结清整个待学包；完成后边界等于今天且积压清空。（AC-C03）
- [ ] **C-06 完成后的次日**：推进到下一业务日；确认只出现新日内容。（AC-C04）
- [ ] **C-07 同日撤销**：完成后在同一业务日撤销；确认边界恢复为完成动作的前值，原包重新出现。（AC-C05）
- [ ] **C-08 跨日拒绝撤销**：完成后推进到下一业务日再撤销；确认操作被拒绝、原因可见、边界不变。（AC-C06）
- [ ] **C-09 完成请求幂等**：并发发送两次相同幂等键；确认只有一次边界变化和一个完成事件。（AC-C07）
- [ ] **C-10 多设备冲突**：设备 A 完成后，设备 B 用旧版本撤销；确认服务端拒绝静默覆盖并要求刷新。（FR-C07）
- [ ] **C-11 跨午夜页面**：页面停留跨过业务日边界；确认提示刷新并重新计算包，旧日请求不结清新日。（异常场景 2）
- [ ] **C-12 时区变更**：今天修改时区；确认旧内容和历史不重写，新时区从下一业务日生效。（FR-C08）

## 3. 测试会话与指纹

- [ ] **Q-01 新会话**：连续开始两次同类型测试；确认会话 ID 和不可预测随机种子不同。（AC-Q01）
- [ ] **Q-02 刷新恢复**：刷新进行中的测试；确认会话 ID、题目和顺序不变。（AC-Q01）
- [ ] **Q-03 近期不重复**：在充足题库连续创建超过默认窗口数量的会话；每个新指纹不属于创建前最近 `N` 个同类型指纹。（AC-Q02）
- [ ] **Q-04 指纹定义**：固定题目但改变 `variant_id` 或展示顺序；确认指纹随实际序列改变且相同输入稳定得到相同值。（FR-Q03）
- [ ] **Q-05 并发去重**：两个客户端同时新建同类型会话；确认事务/约束仍满足近期去重。（FR-Q04）
- [ ] **Q-06 题库不足**：限制唯一组合数；确认依次尝试题型变体、顺序、缩短窗口，最后才允许最旧重复。（AC-Q03）
- [ ] **Q-07 降级透明**：确认不足时记录 `INSUFFICIENT_BANK`，开始页和最终报告均说明可能重复。（AC-Q03、AC-Q04）
- [ ] **Q-08 低于最小题量**：题库少到无法形成有效测试；确认阻止开始并提示补充题库。（异常场景 7）
- [ ] **Q-09 最终报告**：完成交卷；确认报告包含总数、正确数、正确率、逐题结果、答案、解释、耗时、错题去向和降级状态。（AC-Q04）
- [ ] **Q-10 过期会话**：令未提交会话过期；确认状态为 `expired` 且不生成伪报告。（FR-Q06）

## 4. 错题巩固

- [ ] **R-01 自动入库**：提交含错误和未答题的测试；确认对应学习项自动进入巩固。（AC-R01）
- [ ] **R-02 幂等写入**：重复同一交卷请求；确认不重复插入，只按规则更新一次计数。（AC-R01）
- [ ] **R-03 排序**：准备不同到期时间和错误次数；确认队列按到期、错误次数和最近错误排序。（FR-R02）
- [ ] **R-04 再次答错**：巩固时答错；确认条目保留、错误信息更新并重新安排复习。（FR-R02）
- [ ] **R-05 掌握**：连续答对达到设置阈值；确认状态为 `mastered` 且离开普通到期队列。（AC-R02）
- [ ] **R-06 删除独立性**：删除允许删除的测试历史；确认错题记录不被静默级联删除。（FR-R04）

## 5. 词典

- [ ] **W-01 全量层级**：Provider 返回多个词性、每个词性多个释义和多个例句；确认全部按原层级与顺序显示。（AC-W01）
- [ ] **W-02 Provider 分页**：结果跨多个允许分页；确认所有页完整合并，无只取第一页现象。（FR-W02）
- [ ] **W-03 缺失字段**：Provider 不返回例句；确认显示“该来源未提供”，不伪造来源内容。（AC-W02）
- [ ] **W-04 生成补充隔离**：若启用生成式补充，确认其单独标识且不混入 Provider 字段。（FR-W03）
- [ ] **W-05 来源信息**：确认显示来源、查询时间、拼写规范化和许可提示。（FR-W04）
- [ ] **W-06 异常净化**：模拟零结果、超时、限流和配额错误；确认提示可行动且页面/日志不显示授权头或 secret。（FR-W04）
- [ ] **W-07 联想与键盘**：逐字输入、拼错并使用上下键/Enter/Escape；确认候选可操作、请求可取消，第三方失败仍返回本地词库候选。
- [ ] **W-08 词形时态**：查询规则动词、不规则动词和兼具名词/动词的词；确认词形标签准确且不把派生词误称为时态。
- [ ] **W-09 大词库回退**：阻断 Free Dictionary API；确认由 Open English WordNet D1 返回完整词性/义项并保留 CC BY 4.0 来源。

## 6. 每日场景表达

- [ ] **T-01 字段完整**：每天恰有三条表达，每条含多义中文、语义核心、两个场景、双语例句、误用提醒与替代说法。（AC-T01）
- [ ] **T-02 日期稳定且跨日不同**：同日刷新内容不变；最近 30 天的主句、词汇和场景表达不重复。（AC-T01）
- [ ] **T-03 功能边界**：站内无口语练习入口，测试题库无写作题；邮件也不生成或展示这些任务。

## 7. 每日邮件

- [ ] **M-01 默认关闭**：新用户未启用邮件；确认不创建外部发送请求。（AC-M01）
- [ ] **M-02 未验证地址**：启用但未验证；确认仍不发送并提示完成验证。（AC-M01）
- [ ] **M-03 正文完整**：启用并验证后，确认邮件包含英文句子、中文释义、1 至 3 条注意事项、微练习和暂停入口。（AC-M02）
- [ ] **M-04 每日幂等**：同日重复调度和重试；确认同模板版本只有一条成功发送记录。（AC-M03）
- [ ] **M-05 限流退避**：模拟 Provider 限流；确认有限退避重试，过窗口后不跨日补发成两封。（FR-M03、异常场景 10）
- [ ] **M-06 与学习解耦**：邮件失败或打开邮件；确认均不改变 `settled_through_date`。（FR-M05）
- [ ] **M-07 隐私**：检查页面、日志和错误；只出现掩码/不可逆标识，没有真实邮箱、正文或授权头。（AC-M03）
- [ ] **M-08 暂停**：关闭邮件后确认待执行任务取消，并显示已提交邮件可能无法撤回的说明。（异常场景 11）

## 8. 移动端、无障碍与安全

- [ ] **U-01 320 像素视口**：检查今日、测试、巩固、词典、设置核心流程；无横向滚动。（AC-U01）
- [ ] **U-02 触控目标**：核心按钮与导航目标至少 44×44 CSS 像素。（AC-U01）
- [ ] **U-03 键盘操作**：仅用键盘完成主导航、开始测试和结清确认；焦点可见且顺序合理。（AC-U02）
- [ ] **U-04 状态表达**：加载、错误、成功和撤销均有文本，不只依赖颜色。（AC-U02）
- [ ] **U-05 对比度**：主要文本与控件状态满足 WCAG 2.2 AA 适用阈值。（FR-U02）
- [ ] **S-01 敏感扫描**：执行 `pnpm scan:sensitive`；确认没有真实邮箱、令牌、secret 或部署专属 ID。（AC-S01）
- [ ] **S-02 内容边界**：检查首页、每日内容、报告和学习反馈；不使用机构合作或成绩保证措辞。（AC-S02）
- [ ] **S-03 Provider 数据边界**：设置页显示每个 Provider 的用途与发送的数据类别；未获同意不发送作文、录音等扩展数据。（隐私边界）

## 9. 发布前证据

- [ ] 保存测试环境版本、业务时区和用例数据说明，不保存真实邮箱或令牌。
- [ ] 记录所有失败项的复现步骤、预期、实际和非敏感日志关联 ID。
- [ ] 执行 `pnpm check` 与 `pnpm test:e2e`，结果全部通过。
- [ ] 确认页面文案自然、简洁，隐私和设置项与实际能力一致。
- [ ] 对未实现的增强项明确标记“未包含”，不以占位 UI 暗示已经可用。
