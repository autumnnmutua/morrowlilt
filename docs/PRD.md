# 个人雅思英语学习网站产品需求文档

| 项目     | 内容                                           |
| -------- | ---------------------------------------------- |
| 文档状态 | 阶段 1 基线，可进入设计与技术拆解              |
| 产品性质 | 单用户优先、移动端优先的独立英语学习工具       |
| 学习目标 | 雅思及以上难度的词汇、听读写迁移与真实场景英语 |
| 工程代号 | Daily English Study；正式名称后续确定          |

## 1. 声明与产品边界

本产品是独立开发的个人学习工具。产品不复制、抓取或镜像受限制的试题材料；每日话题和练习必须为自建、获得许可或来自允许使用的 Provider。站内使用自然的学习反馈语言，不展示机构合作或成绩保证措辞。

## 2. 背景、目标与成功信号

用户需要一个每天打开即可行动的学习入口，减少选题成本，同时保证遗漏内容不会悄悄消失。产品通过每日学习包、随机测试、错题巩固、词典检索与邮件微练习形成闭环。

### 2.1 产品目标

1. 用户在手机上 30 秒内看懂今天及积压的学习任务。
2. 用户能完成每次可追溯、近期不重复的词汇或短语测试，并得到最终报告。
3. 错题自动进入巩固流程，后续能再次出现并记录掌握变化。
4. 每日内容可从联网 Provider 更新，同时在上游失败时保持可学习。
5. 邮件提醒幂等、可关闭，不泄露用户隐私。

### 2.2 MVP 成功信号

- 日学习包打开成功率不低于 99%（不含用户离线且无缓存的首次访问）。
- 测试开始后可生成最终报告的比例不低于 98%。
- 同一用户近期窗口内的题集指纹无重复；发生降级时有明确记录和用户提示。
- 每个业务日最多产生一封成功投递的每日邮件任务。
- 所有“已学习/撤销”操作均可通过状态记录解释。

## 3. 目标用户与核心场景

### 3.1 目标用户

- 主要用户：正在备考雅思、希望每天短时稳定学习的个人用户。
- 使用特征：以手机访问为主；学习时间不固定；可能连续数天未登录。
- MVP 账户模型：单用户优先。身份保护可在部署时由访问控制层提供，不在应用内自建复杂账户系统。

### 3.2 用户故事

1. 作为学习者，我希望打开首页就看到今天和所有未结清日期的内容，以免漏学。
2. 作为学习者，我希望一次点击结清当前整个待学包，第二天只看到新增内容。
3. 作为学习者，我希望能在同一业务日撤销误触，恢复点击前的积压状态。
4. 作为学习者，我希望每次词汇或短语测试形成独立会话，题目近期不重复，并在结束时获得报告。
5. 作为学习者，我希望错题自动进入巩固，以后能再次练习。
6. 作为学习者，我希望搜索单词后看到词典 Provider 返回的全部词性、释义和例句，而不是被产品任意截断。
7. 作为学习者，我希望每天获得三条适合朋友聊天、线下互动和游戏交流的地道表达，并理解语气、隐喻和易错点。
8. 作为学习者，我希望每天收到包含英文句子、中文释义、注意事项和微练习的邮件，并能关闭它。

## 4. 范围

### 4.1 MVP

- 首页每日学习包与精确定义的结清/撤销规则。
- 联网获取每日内容、按日期固化快照、失败时使用最近有效缓存或内置应急内容。
- 随机单词测试、随机短语测试、独立会话、近期指纹去重与最终报告。
- 错题自动入库、基础巩固队列与再次作答结果。
- 词典搜索，完整展示 Provider 响应范围内的词性、释义和例句。
- 每日三条真实场景表达，含多个中文义项、语气、场景、例句、易错点和正式语域迁移。
- Resend 每日邮件与幂等发送记录。
- 移动端优先的清新界面、键盘可用和基础无障碍。

### 4.2 增强项

- 难度自适应、间隔重复算法、学习连续天数与趋势图。
- 多设备同步、多用户账户、数据导出与删除入口。
- 更完整的发音音频、词源关系图和个性化复习反馈。
- 多 Provider 自动切换、内容编辑后台、离线 PWA。

### 4.3 明确不做

- 官方真题库、官方考试模拟器或官方分数承诺。
- 抓取不允许再分发的词典、教材或考试内容。
- MVP 内的付费订阅、社交排行、教师后台和公开用户主页。
- 未经用户同意保存录音、作文或用于模型训练。
- 自动代替用户报名考试、登录考试机构或发送营销邮件。

## 5. 术语与时间模型

- **业务时区**：用户设置中的 IANA 时区；MVP 初始默认值由设置页首次确认，不由浏览器静默永久决定。
- **业务日**：业务时区中从 00:00:00 到 23:59:59.999 的自然日，键为 `YYYY-MM-DD`。
- **每日内容快照**：某业务日首次成功生成后固化的内容版本。联网 Provider 后续更新不改写已出现的快照。
- **待学包**：从 `settled_through_date` 的下一天到当前业务日（含）所有每日内容快照按日期升序叠加后的集合。
- **`settled_through_date`**：用户已整体结清到哪一个业务日；它代表连续结清边界，不代表每项内容逐条完成。
- **测试会话**：从生成题目到提交或过期的独立记录，题目在会话开始后不可被 Provider 更新改写。
- **题集指纹**：对按实际展示顺序排列的 `question_id:variant_id` 序列及测试类型计算的稳定哈希。

## 6. 信息架构

### 6.1 主导航

1. **今日**：日期、待学天数、叠加后的学习内容、三条场景表达、已学习按钮与同日撤销。
2. **测试**：单词测试、短语测试、进行中会话与最近报告。
3. **巩固**：错题队列、待复习数量、作答与掌握状态。
4. **词典**：搜索框、查询历史、完整词典结果。
5. **设置**：业务时区、邮件、学习偏好、Provider 状态和隐私操作。

### 6.2 页面层级

- `/`：今日页。
- `/quiz`、`/quiz/session/:id`、`/quiz/report/:id`：测试入口、会话、报告。
- `/review`：错题巩固。
- `/dictionary`：词典搜索。
- `/settings`：设置。

移动端使用底部主导航；桌面端可转换为侧边栏。核心操作不得仅依赖悬停。

## 7. 详细功能需求

### 7.1 每日内容与联网更新

**FR-D01** 系统按业务日生成内容快照。相邻业务日的快照必须有不同的 `content_date` 和 `content_version`，核心学习项不得完全相同。

**FR-D02** 每日内容可从配置的内容 Provider 联网获取。系统保存来源、拉取时间、内容版本、许可/归属提示及生成方式，不向前端暴露 secret。

**FR-D03** 同一业务日首次成功快照一经用户看到或进入待学包就保持稳定；Provider 更新只影响尚未生成的日期。管理员式强制重建不属于 MVP。

**FR-D04** Provider 超时、限流、格式错误或内容安全检查失败时，依次使用该日已保存快照、最近有效缓存、内置且标注为应急的原创内容。三者都不可用时显示可重试错误，不把空白页标为已学习。

**FR-D05** 每日学习内容至少包括三个带词性、完整中文释义和中英例句的词汇项，以及三条带真实场景拆解的地道表达。

### 7.2 打卡、结清与叠加规则

**FR-C01 默认未学习。** 新业务日开始或用户未点击任何按钮时，该日状态为 `unsettled`。页面浏览、滚动、打开卡片、测试完成和邮件打开都不得自动推进 `settled_through_date`。

**FR-C02 待学包计算。** 若 `settled_through_date = S`，当前业务日为 `T`，待学包包含 `(S, T]` 内每一个自然业务日的快照。若尚无结清记录，从用户启用学习计划的 `start_date` 起算。未来日期永不进入待学包。

**FR-C03 未学习不推进。** 用户保持默认状态或显式选择“今天先不学”，均不得改变 `settled_through_date`。次日进入 `T+1` 后，系统展示原待学包加上 `T+1` 的新内容。

**FR-C04 整包结清。** 用户在业务日 `T` 点击“整个待学包已学习”并确认后，系统以原子操作把 `settled_through_date` 更新为 `T`，记录操作前边界、操作时间和业务日。该动作结清截至当天的所有未结清日期，而非只结清当天一张卡片。

**FR-C05 次日行为。** 整包结清成功后，当日显示已结清状态；下一个业务日只显示新业务日内容，不重复已结清内容。

**FR-C06 同业务日撤销。** 只要当前业务日仍为完成动作发生的 `T`，用户可点击“撤销本次已学习”。系统原子恢复该动作记录的 `previous_settled_through_date`，本次待学包重新出现。跨过业务日边界后普通用户不能撤销；MVP 不提供跨日补改，以避免历史边界歧义。

**FR-C07 并发和幂等。** 同一完成请求携带幂等键；重复提交只能产生一次状态变化。两个设备竞争时以服务端事务为准，客户端刷新为最新边界，并明确提示状态已变化。

**FR-C08 时区变化。** 修改业务时区不重写既有 `content_date` 和结清历史；新时区从确认后的下一个业务日生效。同一天不得通过反复改时区获得多次撤销窗口。

#### 状态图文字描述

1. `UNSETTLED`：默认状态。事件“打开/关闭页面”“点击今天先不学”均留在本状态。
2. `UNSETTLED --确认整个待学包已学习--> SETTLED_TODAY`：事务写入 `settled_through_date = 当前业务日` 和前值快照。
3. `SETTLED_TODAY --同业务日撤销--> UNSETTLED`：恢复前值；若并发状态已被更新则拒绝静默覆盖并要求刷新。
4. `SETTLED_TODAY --进入下一业务日--> UNSETTLED`：结清边界保留，待学包只含新日内容。
5. `UNSETTLED --进入下一业务日--> UNSETTLED_WITH_BACKLOG`：边界不变，旧内容与新内容叠加。

### 7.3 随机单词与短语测试

**FR-Q01** 每次点击开始测试都创建新的 `quiz_session_id`、不可预测随机种子、题目快照和开始时间；单词与短语是不同测试类型。

**FR-Q02** 候选题来自当前有效题库，并应用难度、已学范围和巩固优先级。选择过程使用无偏随机抽样；测试开始后题目和答案版本固定。

**FR-Q03 近期指纹不重复。** 系统对测试类型、按展示顺序排列的 `question_id:variant_id` 序列计算稳定指纹。新会话的指纹不得与该用户同类型最近 `N` 个已创建会话相同，MVP 默认 `N=20`，最终值可在设置中选择。

**FR-Q04 重采样。** 若生成指纹命中近期窗口，系统更换题目、题型变体或顺序并重试，最多重试一个可配置但有上限的次数；服务端用唯一约束或事务避免并发会话得到相同近期指纹。

**FR-Q05 题库不足降级。** 当可组合数量不足以满足窗口时，按以下顺序降级：先更换题型变体，再更换展示顺序，再缩短去重窗口但不得低于可实现的最大唯一组合数。仍无法避免时允许最旧指纹重复，必须在会话记录写入 `degraded_reason=INSUFFICIENT_BANK`，并在开始页提示“题库较小，本次可能包含近期练习过的内容”。不得宣称数学意义上的永久不重复。

**FR-Q06** 交卷后生成最终报告：总题数、正确数、正确率、各题结果、正确答案、简短解释、耗时、错题去向、是否发生去重降级。未交卷的过期会话标记为 `expired`，不伪造报告。

**FR-Q07** 刷新进行中页面应恢复同一会话，不得刷新即换题；用户明确“放弃并新建”才创建新会话。

### 7.4 错题巩固

**FR-R01** 每道错误或未作答题在交卷事务中按 `user + learning_item + answer_variant` 幂等写入错题记录，增加错误次数并设置下次复习时间。

**FR-R02** 巩固页按到期时间、错误次数和最近错误优先级展示。再次答错保留并延后；答对增加连续正确次数。

**FR-R03** 达到设置中的掌握阈值后状态变为 `mastered`，不再进入普通到期队列；用户仍可查看或手动恢复。

**FR-R04** 删除测试会话不得默默删除已经形成的巩固记录；数据删除属于独立的隐私操作。

### 7.5 词典搜索

**FR-W01** 用户提交单词后，Worker 调用配置的词典 Provider；前端不得持有 Provider secret。

**FR-W02** 对 Provider 返回的当前条目及其分页，系统展示全部可用词性；每个词性下展示 Provider 返回的全部释义与例句，并保留原有层级和顺序。产品不得为了版面只取第一项。

**FR-W03** Provider 未提供某项时明确显示“该来源未提供”，不得生成内容冒充 Provider 结果。若产品另行生成补充例句，必须单独标为生成内容且不能混入 Provider 字段。

**FR-W04** 结果显示来源名称、查询时间、拼写规范化和适用许可提示。零结果提供拼写建议；限流、超时和配额错误提供可重试提示，不泄露原始请求头或 secret。

### 7.6 每日真实场景表达

**FR-T01** 每个业务日提供三条地道表达，覆盖朋友聊天、线下互动、游戏或网络社区中的自然交流。

**FR-T02** 每条表达包含表达类型、多个常用中文义项、核心隐喻或语义、至少两个具体场景、中英例句、易错点、语气对比、替换表达和正式语域迁移。

**FR-T03** 表达在同一日期的内容快照中保持稳定；最近 30 天不得重复相同句子、词条或场景表达。候选不足时明确失败或切换来源，不静默轮播旧内容。

### 7.7 Resend 每日邮件

**FR-M01** 用户明确启用且收件地址验证后，系统每天在业务时区的设置时段创建一次发送任务。默认关闭，设置页可暂停或恢复。

**FR-M02** 邮件必须从同一每日快照读取英文句子、完整词汇信息、三条场景表达、注意事项、微练习和退订/暂停入口。

**FR-M03** 使用 `user + business_date + template_version` 作为幂等键；重复调度、重试或 Worker 重启不得产生同业务日同版本的第二封成功邮件。失败采用有限次数退避重试，并记录非敏感错误分类。

**FR-M04** 收件地址、发件身份和 Resend secret 只在受控存储或 secret 管理中出现。日志默认使用不可逆标识，不输出真实邮箱、邮件正文或请求授权头。

**FR-M05** 邮件发送失败不影响每日学习包生成，也不得推进 `settled_through_date`。

### 7.8 移动端优先与视觉

**FR-U01** 首要设计宽度为 320 至 430 CSS 像素；核心阅读和操作无需横向滚动，触控目标至少 44×44 CSS 像素。

**FR-U02** UI 使用充足留白、清晰层级、低干扰的浅色或自然色调；清新不等于低对比度。文本和交互状态满足 WCAG 2.2 AA 的适用对比度与键盘要求。

**FR-U03** 长待学包按日期分组并默认显示积压天数。结清按钮持续说明“将结清截至今天的全部待学内容”，避免误以为只完成当前卡片。

**FR-U04** 加载、空、错误、离线、成功和撤销状态均有文本反馈，不能只靠颜色。

## 8. 数据与状态概要

- `user_settings`：业务时区、开始日期、测试偏好、邮件开关与时段。
- `daily_content_snapshots`：业务日、版本、来源、内容及创建时间，业务日唯一。
- `learning_progress`：`settled_through_date` 与版本号。
- `settlement_events`：动作业务日、前值、后值、幂等键、是否撤销。
- `quiz_sessions`：类型、题目快照、指纹、状态、降级原因和时间。
- `quiz_answers`：会话题目、作答、正确性和解释快照。
- `mistake_items`：学习项、错误次数、连续正确数、下次复习时间和状态。
- `dictionary_cache`：规范化查询、Provider、原始层级结果、许可元数据和过期时间。
- `mail_deliveries`：业务日、模板版本、幂等键、状态和非敏感错误分类。

所有写状态的 API 都需要输入验证、幂等策略和服务端时间判断。客户端日期只用于显示，不作为结清或发信的权威依据。

## 9. 异常与边界场景

1. **连续多日未登录**：首次回来时生成或补齐从结清边界到今天的全部快照，按日期叠加；某日 Provider 失败则使用该日降级内容。
2. **跨午夜停留页面**：检测服务端业务日变化，提示刷新并重新计算待学包；旧日完成请求不得被当作新日完成。
3. **完成时网络中断**：客户端用同一幂等键重试并查询最终状态，不依据本地动画推定成功。
4. **同日撤销后再次完成**：允许生成新事件，仍需记录新的前值与幂等键。
5. **两设备同时完成/撤销**：乐观版本冲突返回明确错误，禁止后写静默覆盖先写。
6. **内容 Provider 返回重复或不安全内容**：拒绝快照并进入降级链路。
7. **测试题库少于题量**：减少题量至至少可形成有效测试的下限；若连下限都达不到，阻止开始并提示补充题库。
8. **会话中途题库更新**：进行中会话继续使用题目快照。
9. **词典超大响应**：服务端完整获取 Provider 允许的分页；前端可折叠或虚拟渲染，但不得丢弃条目。
10. **邮件 Provider 限流**：退避重试；超过当日容忍窗口后标记失败，不跨日补发导致一天两封。
11. **用户关闭邮件**：尚未执行的任务取消；已提交给 Provider 的邮件不可保证撤回，界面说明边界。
12. **时钟和夏令时变化**：以 IANA 时区库解析业务日，按日期幂等而非按固定 24 小时间隔发送。

## 10. 非功能需求

- **性能**：移动网络下首屏优先；每日页核心内容避免被非关键 Provider 请求阻塞。
- **可靠性**：状态写入使用事务或等价原子机制；计划任务与外部调用可重试且幂等。
- **安全**：secret 仅存于运行环境；输入按 schema 校验；外部错误经过净化；依赖和兼容日期定期更新。
- **可观测性**：记录请求 ID、非敏感状态、耗时、降级原因；禁止记录真实邮箱、令牌、完整作文或邮件正文。
- **可测试性**：随机逻辑可注入固定种子；业务时钟可替换；Provider 通过接口模拟；每条 MVP 需求有自动或人工验收路径。
- **兼容性**：当前稳定版 Chrome、Safari、Edge 的最近两个主要版本；320 像素宽度起可用。

## 11. 隐私边界

- 最小化收集：MVP 仅保存实现学习、测试、巩固和邮件所需的数据。
- 真实邮箱属于敏感个人数据，页面只显示掩码，服务端日志不得输出原值。
- 不把用户作文、录音、搜索历史或作答用于模型训练，除非未来另行取得明确、可撤销的同意。
- 第三方 Provider 仅接收完成请求所必需的数据；设置页需要显示 Provider、用途和数据类别。
- 后续提供导出、删除与保留期设置；在其实现前，不宣称已经支持完整账户自助删除。

## 12. 冲突处理与产品决定

采用“最少惊讶原则”作出以下决定，不阻塞当前阶段：

1. **“每日联网更新”与“积压内容稳定”冲突**：按业务日首次成功生成后固化快照。更新影响未来日期，不改写用户已经看到的旧内容；这样报告和结清历史可重现。
2. **“每次测试都不一样”与有限题库冲突**：定义为同类型近期 `N` 个题集指纹不重复，而非永久不重复；题库不足时透明降级。
3. **“点击已学习”可能被理解为只完成当天**：按钮文案与确认框明确为“整个待学包已学习”，因为需求指定结清截至当天的全部积压。
4. **“全部词典内容”与页面长度冲突**：完整保留 Provider 返回的全部词性、释义和例句，前端通过折叠/虚拟渲染解决长度，不截断数据。
5. **邮件每天发送与隐私冲突**：邮件默认关闭，只有验证地址并明确启用后才发送。
6. **业务日撤销与跨时区冲突**：以服务端记录的动作业务日判断；时区变更次日生效，不重写历史。

## 13. 逐条验收标准

### 每日内容与打卡

- **AC-D01** 给定连续两个业务日，生成的快照日期与版本不同，核心学习项不完全相同。
- **AC-D02** Provider 正常时保存来源与快照；随后上游改变，同一日期用户仍看到原快照。
- **AC-D03** Provider 依次发生超时、无缓存和无应急内容时，页面显示可重试错误，结清按钮不可误导性成功。
- **AC-C01** 新业务日只浏览页面后，`settled_through_date` 保持不变。
- **AC-C02** 边界为三天前且今天未学习时，待学包按日期包含边界后的三天内容；次日再增加一天。
- **AC-C03** 在今天确认整个待学包已学习后，边界变为今天，积压清空。
- **AC-C04** 次日进入时，只出现次日新内容。
- **AC-C05** 同一业务日撤销后，边界精确恢复完成前值，原待学包重新出现。
- **AC-C06** 跨业务日撤销被拒绝并解释原因；历史边界不变。
- **AC-C07** 重复提交同一幂等键只产生一个完成事件。

### 测试与巩固

- **AC-Q01** 连续开始两次测试得到不同会话 ID；刷新进行中会话不换题。
- **AC-Q02** 在题库充足时，新指纹不属于同类型最近 `N` 个指纹。
- **AC-Q03** 人为限制题库后系统按既定顺序降级，记录 `INSUFFICIENT_BANK` 并展示提示。
- **AC-Q04** 交卷报告包含总数、正确数、正确率、逐题结果、答案、解释、耗时和降级状态。
- **AC-R01** 错题交卷后只生成一条幂等巩固记录并增加计数；重复交卷不重复插入。
- **AC-R02** 连续答对达到阈值后条目变为 `mastered`，不再出现在普通到期队列。

### 词典、场景表达与邮件

- **AC-W01** 模拟 Provider 返回多个词性、每个词性多个释义和例句，页面完整显示全部层级与来源。
- **AC-W02** Provider 缺少例句时显示“该来源未提供”，不伪造 Provider 例句。
- **AC-W03** 输入字母后显示本地大词库、历史与可用在线来源合并的联想词；第三方失败时仍有本地候选。
- **AC-W04** 每个动词明确显示原形、第三人称、现在分词、过去式和过去分词；多词性的全部义项均有中文补充。
- **AC-T01** 每日恰有三条场景表达，字段完整，最近 30 天的表达、词条与主句不重复。
- **AC-M01** 邮件未启用或地址未验证时不创建发送请求。
- **AC-M02** 启用后邮件含英文句子、中文释义、注意事项、微练习和暂停入口。
- **AC-M03** 同一业务日重复触发调度，只有一条成功发送记录；日志无真实邮箱。

### 体验、安全与边界

- **AC-U01** 在 320 像素宽视口完成浏览、测试入口和结清操作，无横向滚动，核心触控目标不小于 44×44 像素。
- **AC-U02** 仅用键盘可到达并操作核心控件；状态不只用颜色表达。
- **AC-S01** 仓库与构建产物扫描不到真实邮箱、令牌、secret 或部署专属 ID。
- **AC-S02** 所有页面和生成式反馈均不声称官方身份、官方真题或官方成绩。

## 14. 以后由用户在设置页选择的参数

以下参数不阻塞 MVP 文档，但不能由开发者永久硬编码：

- 业务时区与学习计划开始日期。
- 目标难度与实用场景偏好。
- 每日词汇/短语数量和真实场景偏好。
- 测试题量、题型、巩固题占比、近期去重窗口 `N`（建议默认 20）。
- 错题掌握阈值和每日巩固上限。
- 内容 Provider、词典 Provider及允许的数据共享范围。
- 邮件开关、收件地址、业务时区内发送时段和周末是否发送。
- 显示语言、字号、减少动画、高对比度与主题偏好。
