沿 Worker 路由、Access 身份映射、D1 迁移与查询、学习结清、每日内容、邮件绑定/投递、测评和错题、词典以及 React 请求层审阅；保留历史数据库表与数据兼容性。

## 精简边界

Content Provider 工厂由网页和调度共用，已知领域错误统一响应；邮件预览不再额外生成旧式 daily_content 与派生学习包。旧表及管理员内容再生接口仍保留兼容，未删除用户数据。没有仅因出现次数少而删除依赖或导出接口。

## 验证命令

`pnpm check`、`pnpm test:e2e`、`pnpm audit --audit-level moderate`、`node scripts/scan-public-export.mjs --tracked`、`git diff --check`。所有外部邮件测试使用 mock，不向真实收件人发送。

本地验证：26 项前端测试、126 项 Worker 测试通过；9 项浏览器测试通过；266 个依赖的许可证检查通过，依赖审计未发现已知漏洞。

额外检查：并发更换邮箱使用独立确认邮件去重键；重复退订请求不能覆盖后续重新绑定；平台原收件地址在新邮箱待确认时保持有效，明确退订与停用仍停止发送。

## 仍有边界

- 大量欠学日期目前由 API 全量保留；许多缺失日期需要在线生成时，首次请求仍可能较慢。没有为速度静默丢弃内容。
- Cron 仍按账号顺序处理；大规模用户部署应引入队列及负载测试。本次回归覆盖错误隔离，不代表已经完成大规模压测。
- Provider 已接受邮件不等于邮箱已投递到收件箱；额度、发送域信誉、收件规则及外部服务可用性仍影响送达。
- 内置种子有限，严格不重复依赖在线生成供应。测试与静态审阅不能保证任意未来输入均无缺陷。
